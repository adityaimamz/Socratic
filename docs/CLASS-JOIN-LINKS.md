# Link undangan kelas

Pengajar menyimpan kelas, membukanya pada **Kelas & peserta**, lalu membuat dan menyalin link undangan. Murid membuka link, mendaftar atau masuk dengan email/Google, dan otomatis bergabung setelah identitas email terverifikasi. Pengajar tidak perlu memasukkan email murid terlebih dahulu. Kelas yang sudah ditautkan ke ujian menggunakan aturan keanggotaan kelas yang sama seperti penambahan lewat email.

Link berlaku default 7 hari dengan batas 40 peserta baru; pengajar dapat memilih 1–30 hari dan 1–1.000 peserta baru. Satu kelas memiliki satu link saat ini. Pembuatan link baru membatalkan link lama dan mengatur ulang jumlah penggunaan, tanpa menghapus anggota. Penonaktifan link juga mempertahankan anggota. Anggota yang sudah terdaftar dapat mengulang join dengan link yang masih berlaku tanpa memakai kuota lagi.

Token acak 256 bit ditampilkan hanya setelah pembuatan; database menyimpan SHA-256 token. Jika link belum disalin sebelum meninggalkan halaman, buat link baru. Endpoint pengelolaan hanya mengizinkan pemilik kelas/pengajar atau admin. Endpoint join menggunakan identitas email terverifikasi dari sesi server, menetapkan peran peserta untuk akun baru, menolak akun nonaktif dan akun/undangan staf, dan tidak menerima email, peran, atau identitas dari body klien. Lock kelas/link menserialkan join dengan pergantian link dan pemeriksaan kuota. Semua RPC baru hanya dapat dipanggil `service_role`.

Pendaftaran dari link tidak menambahkan profil atau anggota sebelum verifikasi email. Login biasa tetap memerlukan undangan email/profil. Tujuan setelah OAuth/konfirmasi dibatasi pada `/join/<token>`; pemulihan kata sandi tetap menuju halaman reset. Cookie HTTP-only sementara menyimpan tujuan join selama satu hari untuk konfirmasi email di browser yang sama. Query `next` pada callback mempertahankan tujuan pada alur PKCE. Tautan konfirmasi khusus yang memakai `/auth/confirm` perlu meneruskan `next=/join/<token>` bila konfirmasi dibuka di browser lain; bila tidak, murid dapat membuka kembali link kelas setelah mengaktifkan akun.

## Penerapan

Perubahan membutuhkan migrasi `202610270014_class_join_links.sql` sebelum deployment aplikasi. `npm run supabase:check` menolak deployment bila RPC migrasi ini belum tersedia. Pastikan pengaturan redirect Supabase mengizinkan origin aplikasi dengan `/auth/callback` beserta query `next`; panduan project memakai URL aplikasi dari `NEXT_PUBLIC_APP_URL`. Pengiriman email nyata tetap bergantung pada konfigurasi Auth/SMTP Supabase. Persetujuan deploy dan penerapan migrasi hosted diperlukan terpisah.

## Validasi lokal

Email dan OAuth di fixture adalah simulasi, bukan bukti pengiriman email atau login Google hosted.
